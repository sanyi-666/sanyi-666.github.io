Linux 入门：从 ls 到第一个 shell 脚本

2026-10-28

刚开始用 Linux 的时候，最容易犯的错是把 Windows 的习惯带过来： 以为所有东西都在「桌面」上，以为删掉的文件在回收站里。 Linux 的思维方式不太一样——一切都是文件，一切都可以用命令说清楚。

先弄清楚自己在哪

pwd          # 我在哪个目录
ls -alh      # 这个目录里有什么（含隐藏文件、大小可读）
cd /etc      # 进入根目录下的 etc
cd ~         # 回到家目录
cd -         # 回到上一个目录

/etc 和 etc 是两回事：前者从根目录开始找， 后者从当前目录开始找。很多「找不到文件」的报错，都是这个差别造成的。

对文件做点什么

mkdir -p notes/linux   # 递归建目录
touch a.txt            # 建一个空文件
cp a.txt b.txt         # 复制
mv b.txt notes/        # 移动（也可以用来改名）
rm -r notes            # 删目录，删之前先 ls 看一眼

看内容、找内容

cat a.txt              # 输出全部内容
less a.txt             # 分页看，q 退出
head -5 a.txt          # 前 5 行
grep -rn "keyword" .   # 递归搜索当前目录

写第一个脚本

把这几天敲过的命令存下来，就是脚本了。

#!/bin/bash
# backup.sh —— 把笔记目录打包到 backups/

mkdir -p backups
tar -czf "backups/notes-$(date +%Y%m%d).tar.gz" notes
echo "备份完成：$(ls -1t backups | head -1)"

给执行权限，然后运行：

chmod +x backup.sh
./backup.sh

第一行 #!/bin/bash 告诉系统用哪个解释器跑这个文件； chmod +x 是给它执行权限。这两步缺一不可， 也是新手最容易漏的地方。

脚本跑通的那一刻，命令行就不再是「背命令」了， 而是可以把自己的重复劳动写成程序。这是我觉得 Linux 最好玩的部分。
